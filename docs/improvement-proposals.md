# アプリ改善提案

## 1. 現状

現在のアプリは、Leaflet と OpenStreetMap による東京中心の地図表示、テーマ切り替え、ヘルプ表示を提供している。構成はシンプルで、`MapComponent` は固定位置のマーカーを表示し、サーバー側には SQLite のメッセージ取得 API がある。

今後は「地図を確認する」だけでなく、ユーザーが目的地を探し、必要な情報を安全かつ快適に扱えるアプリへ段階的に拡張する。

## 2. 実装済み

- 現在地ボタンから Geolocation API を呼び出し、取得した座標へ地図を移動できるようにした。
- 現在地の取得中・非対応・失敗をボタンの状態とメッセージで通知するようにした。
- ヘルプ表示をクリックでも開閉できるようにし、`aria-expanded` と Esc キーに対応した。

## 3. 優先度の高い改善

### P0: 現在地取得と検索機能

- ブラウザの Geolocation API で現在地へ移動するボタンを追加する。
- 地名・住所検索を追加し、検索結果を地図上で選択できるようにする。
- 位置情報の利用目的、許可されない場合の代替動作、検索エラーを画面上で明示する。
- 座標の妥当性を検証し、検索 API のタイムアウト・レート制限・帰属表示などの利用条件を守る。

**完了条件:** 現在地の取得に失敗しても地図操作を継続でき、検索語から候補を選んで地図を移動できる。

### P0: レスポンシブ UI とアクセシビリティ

- 地図操作ボタンをモバイルでも押しやすいサイズと配置にする。
- キーボード操作、フォーカス表示、`aria-label`、スクリーンリーダー向けの状態通知を整備する。
- ヘルプをマウスホバーだけに依存しない開閉式パネルにし、Esc キーと外側クリックに対応する。
- 地図だけに情報を依存せず、選択地点の名称・住所をテキストでも表示する。

**完了条件:** キーボードのみで主要操作を実行でき、画面幅 320px からデスクトップまで情報が欠落しない。

### P1: 地図状態の保存と共有

- 中心座標、ズーム、検索結果を URL パラメーターに反映する。
- URL を再読み込み・共有したときに同じ表示状態を復元する。
- 不正な座標や極端なズーム値は安全な既定値へ戻す。
- お気に入り地点をブラウザへ保存し、削除・名称変更できるようにする。

**完了条件:** 共有 URL から同一の地図状態を再現でき、壊れた URL でも画面がクラッシュしない。

## 4. 品質・運用面の改善

### P1: データ層と API の整理

- 現在の単一メッセージ API を、地点・お気に入りなどの用途ごとの API に分離する。
- SQLite の初期化・接続・マイグレーションを明確にし、開発環境と本番環境のデータ保存先を設定で切り替える。
- API の入力検証、レスポンス型、エラー形式を統一する。
- 本番の複数プロセス環境で SQLite を利用する場合のロック、バックアップ、書き込み制約を確認する。

### P1: テストと自動検証の拡充

- 検索、現在地取得の成功・拒否・タイムアウト、URL 復元、保存データ破損をテストする。
- API の正常系・異常系と、データベースのマイグレーションを統合テストする。
- ESLint、型チェック、ビルドを CI で実行し、主要ブラウザでの E2E テストを追加する。
- OpenStreetMap タイルや外部検索 API が利用できない場合のモックを用意する。

### P2: パフォーマンスと障害時 UX

- 地図コンポーネントを必要な画面でだけ読み込み、初期表示時の JavaScript を抑える。
- 検索入力にデバウンスを適用し、リクエストのキャンセルと結果のキャッシュを行う。
- タイル・検索 API の失敗時に再試行、オフライン状態、利用制限を分かりやすく表示する。
- Web Vitals と API 応答時間を計測し、改善前後を比較できるようにする。

## 5. 推奨する実装順序

1. 地図操作 UI の共通部品化とアクセシビリティ対応
2. 現在地取得と検索機能（入力検証・エラー表示を含む）
3. URL による状態保存と共有
4. お気に入り保存とデータ層/API の整理
5. テスト、CI、監視、外部サービス障害時の UX

## 6. 判断が必要な事項

- 検索プロバイダーとして Nominatim を採用するか、運用要件に応じて別サービスを選ぶか。
- お気に入りをブラウザ限定にするか、ユーザー認証とサーバー保存まで実装するか。
- SQLite を継続利用するか、複数ユーザー・複数インスタンスを前提に別の永続化基盤へ移行するか。
- ダークモード時に地図タイルも切り替えるか、標準タイルを維持するか。
